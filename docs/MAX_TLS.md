# Доверенные CA только для MAX

Официальный API использует `https://platform-api2.max.ru`; документация MAX
требует добавить сертификат Минцифры в доверенные. Источник сертификатов —
https://www.gosuslugi.ru/crt. Не скачивать CA с обходом проверки TLS и не брать
сертификат самого API-сервера в качестве доверенного корня.

## Ограничение области доверия

`MAX_CA_FILE` указывает на PEM-файл с выбранными CA. Клиент MAX создаёт собственный
SSLContext с обычными корнями и добавляет этот bundle только в свой TCPConnector.
Имя сервера и цепочка сертификата проверяются, `CERT_REQUIRED` сохраняется.
Промежуточный CA не считается самостоятельным корнем (`PARTIAL_CHAIN` отключён).
Перенаправления HTTP для запросов с токеном запрещены.

Нельзя задавать `SSL_CERT_FILE`, `REQUESTS_CA_BUNDLE`, устанавливать эти CA в
системное хранилище или отключать TLS-проверку ради интеграции MAX. Другие клиенты
(Telegram/DeepSeek/urllib по умолчанию) не получают это дополнительное доверие.
Неверный/отсутствующий файл при явно заданном `MAX_CA_FILE` блокирует запуск.
Отсутствие самой переменной сохраняет стандартное доверие, без дополнительных CA.

предоставленного корня; это проверка цепочки, не независимое доказательство
подлинности источника. Источник доверенного корня должен быть проверен владельцем.

Сертификаты не копируются в Git и не загружаются автоматически при сборке.
На VPS bundle хранится отдельно от обновляемого контейнера, монтируется read-only.
При замене CA проверить официальный источник, подписи, сроки и отпечатки заново.

## Coolify

1. Загрузить три PEM-файла на VPS в `/srv/seven-crowns-max-ca/`.
2. Объединить в `/srv/seven-crowns-max-ca/max-ca.pem`, режим чтения 644,
   каталог 755; закрытых ключей там быть не должно.
3. В приложении сделать read-only mount каталога в `/run/max-ca` (не в nginx).
4. Runtime-переменная `MAX_CA_FILE=/run/max-ca/max-ca.pem`.
5. Развернуть проверенный коммит. Не редактировать файлы внутри работающего
   контейнера: изменения пропадут после Deploy.

## Подписка webhook

```bash
docker exec <bot-container> python scripts/max_subscribe.py \
  --url https://<your-domain>/max/webhook
```

По умолчанию это только GET текущих подписок. Для явного добавления/обновления
того же адреса добавить `--apply`. При чужом URL скрипт остановится без удаления
или изменений. Секреты берутся из окружения, не печатаются и не передаются через
query. TLS context тот же, что у клиента отправки сообщений MAX. Сырые ошибки
API/сеть/DSN/токены не выводятся. `registration_success=true` и `target_found=true`
подтверждают регистрацию, но не заменяют живую проверку входящих/исходящих сообщений.
