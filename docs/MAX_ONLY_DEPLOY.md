# MAX-only: сервер без подключения к Telegram

Режим включается явно: `TELEGRAM_ENABLED=0`. По умолчанию значение `1`, поэтому
существующие Telegram и совместные Telegram/MAX установки сохраняют поведение.

В MAX-only не создаются Telegram Bot/session/proxy, не вызываются `get_me()`
и polling. Основной процесс ждёт SIGINT/SIGTERM; при остановке закрывает MAX,
останавливает игровые воркеры, сохраняет прогресс/снимок и закрывает БД.
Обычные Telegram-уведомления и публикации в канал не отправляются. MAX сохраняет
свои входящие/исходящие очереди и общий GameLoop.

## Переменные окружения

```dotenv
TELEGRAM_ENABLED=0
MAX_ENABLED=1
PROD=1
DATABASE_URL=<внутренняя строка подключения PostgreSQL>
MAX_BOT_TOKEN=<секрет>
MAX_WEBHOOK_SECRET=<секрет>
MAX_WEBHOOK_PORT=8080
ADMIN_IDS=<зарезервированные Telegram ID администраторов>
SUPPORT_CONTACT=<контакт>
LEGAL_DOCS_URL=<HTTPS страницы действующих документов>
MAX_LEGAL_VERSION=<версия документов>
AI_PROVIDER=none
NOTIFY=0
STARS_ENABLED=0
```

`BOT_TOKEN` и `PROXY_URL` можно удалить: в этом режиме они не используются.
MAX требует PostgreSQL даже в dev. Отключение обоих транспортов запрещено.
Неверный порт, отсутствие MAX-токена/секрета выявляются до начала работы мира.

**Telegram /admin и Telegram-алерты в MAX-only недоступны.** `ADMIN_IDS` остаётся
обязательным в PROD для совместимости проверки конфигурации, но само по себе не
даёт MAX-админку. Режим годится для управляемого закрытого теста; он не заменяет
реализацию административных действий MAX и операционного мониторинга.

## Coolify

- Dockerfile из репозитория, Ports Exposes `8080`, без Ports Mappings.
- Включить Consistent Container Names: только один процесс мира.
- Старое приложение остановить. Auto Deploy пока выключить.
- После успешного CI нажать Deploy и проверить commit SHA в журнале сборки.
- Нельзя обходить отсутствие действующих документов черновым URL/версией.

## Проверка на сервере

1. В журнале есть MAX-only, PostgreSQL и запуск MAX webhook, нет Telegram getMe.
2. Через 1–2 минуты контейнер `healthy`, счётчик рестартов не растёт.
3. HTTPS webhook проходит проверку сертификата, GET/HEAD возвращает `405`.
4. `python scripts/max_preflight.py --database` внутри контейнера — только чтение,
   без миграций и раскрытия секретов. Отсутствие BOT_TOKEN в MAX-only допустимо.
5. После регистрации webhook проверить создание героя/согласие/команды.
6. Контролируемый Stop/Start сохраняет героя; журнал сообщает финальный снимок.

Закрытый тест не означает готовность платежей, внешнего ИИ, бэкапов или публичного
релиза. Обратное включение Telegram: `TELEGRAM_ENABLED=1`, рабочий `BOT_TOKEN` и
доступный Telegram API; не запускать второй процесс с тем же миром/токеном.
