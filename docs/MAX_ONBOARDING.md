# Создание героя в MAX

Путь нового игрока: условия → мир «Семи Корон» → «Создать героя» → список рас →
карточка расы → список доступных классов → карточка класса → имя → игровой экран.
«Отмена» возвращает на непосредственно предыдущий экран, в том числе из ввода имени.
`/start` продолжает незавершённый выбор; существующий герой не создаётся заново.

Подпись принятия условий — только `✅ Принимаю условия`. Версия документов передаётся
в скрытом callback payload. Старые уже отправленные текстовые кнопки совместимы.
Согласие на уведомления не включается автоматически.

## Обновление сервера

После развёртывания этой версии **обновить подписку MAX**, чтобы принимать нажатия
callback-кнопок, а не только текстовые сообщения и `/start`:

```bash
docker exec kvlp9nwktlkhhzzb4bvbtzbp python scripts/max_subscribe.py \
  --url https://max.bmv50server.ru/max/webhook --apply
```

Секрет и токен берутся из окружения контейнера; печатать их не нужно.
`MAX_CA_FILE=/run/max-ca/max-ca.pem` и существующее подключение CA оставить без изменений.
Схема PostgreSQL расширяется автоматически при старте: таблица `max_onboarding`,
колонка `max_outbox.image_asset`. Игроки и игровые данные не удаляются.

Состояние выбора хранится в PostgreSQL семь дней. Каждая кнопка привязана к пользователю,
этапу и случайному идентификатору текущего экрана. Повторные и устаревшие кнопки не
подтверждают другой выбор. При потерянном ответе БД после создания герой восстанавливается
из активной записи, а не создаётся второй раз.

## Изображения и доставка

`images/onboarding/`: мир, пять базовых портретов и 25 разрешённых сочетаний раса/класс.
Недоступные сочетания не показываются и отклоняются также в текстовой команде `/create`.
В иллюстрации класса сохраняется внешность выбранной расы, меняются одежда и снаряжение.
Иллюстрация — образ класса, не обещание стартового предмета в инвентаре.

Изображения загружаются в MAX через `/uploads` и multipart-поле `data`, затем отправляются
вместе с описанием и inline-клавиатурой. Токен бота не передаётся на сервер загрузки/CDN.
Загрузка только на HTTPS-домены MAX/CDN; перенаправления отключены, проверка TLS сохранена.
Разрешены только встроенные идентификаторы изображений: произвольные URL и пути запрещены.
Загруженные photo-токены кешируются на время процесса; после рестарта загружаются заново.
Ошибка `attachment.not.ready` приводит к повтору доставки, а не игрового действия.

Исходники PNG локальные; для контейнера и Git используются оптимизированные JPEG.
Механическая конвертация только новой папки, без затрагивания существующих артов:

```bash
python scripts/optimize_images.py --only onboarding --keep-png
```

## Проверка после развёртывания

1. В новом диалоге `/start`: видны условия и чистая кнопка принятия.
2. Принять: изображение мира, краткое описание, «Создать героя».
3. Выбрать человека: портрет, преимущества/недостатки, подтверждение и отмена.
4. Подтвердить, выбрать мага: тот же человек в мантии с посохом, описание класса.
5. Проверить возврат через «Отмена» на всех шагах и устаревшее подтверждение.
6. Подтвердить мага: ввод имени; запрещённое/занятое имя не завершает создание.
7. Ввести допустимое имя: один герой, игровой экран, стандартная игровая клавиатура.
8. Повторить `/start`: игра, не повторное создание. Проверить рестарт на незавершённом выборе.

Автоматические проверки: `test_max_onboarding.py`, `test_postgres_max_onboarding.py`,
регрессия всех MAX-команд и Telegram. Живое отображение медиа в клиенте MAX проверяется
после развёртывания; локальные заглушки API не заменяют эту проверку.

API: [кнопки](https://dev.max.ru/docs-api/use-cases/sending-messages/keyboard),
[загрузка](https://dev.max.ru/docs-api/methods/POST/uploads),
[ответ на нажатие](https://dev.max.ru/docs-api/methods/POST/answers).
